# Report Analysis Guide

How to parse and analyze reports generated by `opsx-report`.

## Report Structure

Reports follow OKF v0.2 format:

```yaml
---
type: OpenSpec Report
title: "Report: <change-name>"
description: "<summary>"
status: stable
tags: [openspec, <schema>, <capability>]
generated:
  by: opsx-report/1.0
  at: <timestamp>
sources:
  - id: proposal
    resource: artifacts/proposal.md
  - id: design
    resource: artifacts/design.md
  - id: specs
    resource: artifacts/specs/
  - id: tasks
    resource: artifacts/tasks.md
stale_after: <date>
---
```

## Extraction Points

### From Frontmatter

| Field | Extract | Use |
|-------|---------|-----|
| `tags` | Skill name, capability-path | Identify related skill |
| `generated.at` | Timestamp | Track when report was created |
| `sources` | Artifact paths | Locate original artifacts |
| `stale_after` | Date | Check if report is stale |

### From Sections

| Section | Extract | Use |
|---------|---------|-----|
| Problem Statement | Why skill exists | Understand purpose |
| Approach | Decisions with rationale | Understand design choices |
| What Changed | Requirements added/modified/removed | Understand scope |
| Implementation | Tasks completed, files created | Understand what was built |
| Validation | Test results, pass/fail | Identify failures to fix |
| Trade-offs | Risks and mitigations | Understand constraints |
| Follow-ups | Deferred work | Identify improvements to make |

## Analysis Patterns

### Pattern 1: Validation Failures

```
IF validation section shows failures:
  → Identify which tests failed
  → Analyze why they failed
  → Fix skill to address failures
  → Re-run validation
```

### Pattern 2: Follow-ups

```
IF follow-ups section has items:
  → List all follow-up items
  → Prioritize by impact
  → Implement highest priority
  → Update changelog
```

### Pattern 3: Trade-offs

```
IF trade-offs section has items:
  → Evaluate if trade-offs are still valid
  → Check if alternatives are now viable
  → Consider upgrading if better option exists
```

### Pattern 4: Generalizable Patterns

```
IF report shows pattern applicable to all skills:
  → Check if skill-creator already covers it
  → If not, update skill-creator
  → Propagate to existing skills
```

## Quality Signals

From report analysis, extract quality signals:

- **Validation pass rate**: Percentage of tests that passed
- **Antipattern count**: Number of antipatterns detected
- **Description trigger rate**: How well description triggers
- **Task completion rate**: Percentage of tasks completed

Use these to measure improvement after changes.
