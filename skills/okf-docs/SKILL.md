# Okf Docs

Author structured documents with mandatory provenance. Every deliverable passes the bundled validator before hand-off.

## Procedure

### 1. Select Document Type

| Intent | `type` value |
|--------|--------------|
| Architecture/design decision | Architecture Decision Record |
| Module reference doc | Module Documentation |
| Workspace directive | SystemDirective |
| Skill definition | Skill |
| Session report | Report / Assessment |

### 2. Apply Frontmatter Contract

```yaml
---
okf_version: "0.2"
type: <from table above>
title: <short name>
description: <one-line summary>
generated: { by: <actor>, at: <ISO 8601> }
sources:
  - { id: <source-id>, resource: <url|path> }
status: draft          # draft | stable | deprecated
stale_after: YYYY-MM-DD
---
```

Actor values for `generated.by`: `<producer>/<version>` (agents) · `human:<id>` (people) · `process:<id>` (automation). Full semantics: [references/okf-spec.md](references/okf-spec.md).

### 3. Attribute Claims

Body claims sourced from `sources:` entries cite via footnotes (`[^source-id]`). No uncited external facts.

### 4. Lifecycle

Set `status: draft` on creation. Flip to `stable` after human review (`verified: { by: human:<id>, at }`). Set `stale_after` when content is time-sensitive. Deprecated docs keep standing but state successor.

### 5. Validate Before Delivery

```bash
bun scripts/validate-frontmatter.mjs <document.md>
```

Envelope must read `pass: true`. Fix named FAIL entries; re-run until clean.

## Gotchas

- Dates are ISO 8601 only — no locale formats.
- `stale_after` must not predate `generated.at`.
- README files are promotional (zero tech detail) — OKF applies to technical docs, wikis, ADRs, directives.
